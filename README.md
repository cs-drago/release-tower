# Release Tower

A daily release monitor for a label product manager or A&R ops lead. Once a day it reads public data for each artist, works out what is working and what is fading, and writes a plain-English brief with a short "do this week" list.

Live: **https://release-tower.vercel.app/the-paradox** · **https://release-tower.vercel.app/alex-crichton**

Each artist gets a standalone page, shared by direct link. The root URL is a neutral landing.

Currently tracking The Paradox, *Proceed With Caution* (Hundred Days / Virgin, out Oct 2 2026), with a nine-day pre-release baseline and release week on the same page, and Alex Crichton (Warner) as a second artist.

## What it answers

- Which track is the organic pick off the release, before anyone decides on a focus track.
- Whether the singles and the catalog lifted when the record dropped, and by how much.
- Where the listeners are versus where the tour is routed.
- Whether short-form is converting the moment or just posting through it.
- Which checklist items are inside their window with the release date approaching.

Everything on the page comes from numbers, not opinions. The brief is generated by rules over the data (see `analyze.py`), so the same data always produces the same sentences and nothing is invented.

## How it works

```
releases.json      what to track: artist IDs, singles, release date, checklist, tour
collect.py         one run = one dated snapshot per artist  ->  data/snapshots/<slug>/<date>.json
analyze.py         snapshots -> data/report-<slug>.json  (deltas, decay flags, cities vs tour, brief)
build_site.py      reports -> site/*.html  (static, no JS framework, no runtime fetches)
deploy.sh          collect -> analyze -> build -> vercel deploy -> health check
```

### Data sources

| Source | What it gives | How |
|---|---|---|
| Spotify Web API | followers, popularity score (0 to 100), discography, track metadata | official, client credentials |
| Spotify public artist and album pages | monthly listeners, top cities, cumulative play counts per track | Apify scraper, with a second scraper as automatic fallback |
| Instagram public profile | followers, post count | Apify |
| TikTok public profile | followers, recent videos with views, likes, comments | Apify |

Play counts are what any listener sees on Spotify: cumulative, exact, shown once a track passes 1,000 plays. Daily rates are the difference between two snapshots, normalized to 24 hours, so a skipped day never looks like a spike. Spotify refreshes displayed counts on a lag of up to a day or two, so a single interval can read low and then catch up. Trust the week, not the day.

Nothing here uses label-internal data. Checklist items the label owns are marked "label-internal" and shown as due or upcoming, never claimed as done or late.

## Setting it up

You need three keys. All are free tiers; the Apify one costs about two cents per artist per day.

1. **Apify token.** Sign up at apify.com, then Settings, Integrations, API token. Add a few dollars of credit or use the free monthly allowance.
2. **Spotify client ID and secret.** developer.spotify.com, Dashboard, Create app (any name, any redirect URI). Copy the client ID and client secret.
3. Copy `.env.example` to `.env` in this folder and paste the three values in. `.env` is gitignored and never leaves your machine.

Then:

```
pip install httpx python-dotenv
python3 collect.py          # ~90 seconds, one dated snapshot per artist
python3 analyze.py          # prints the brief
python3 build_site.py       # writes site/, open site/index.html
```

`deploy.sh` does all of that and publishes `site/` to Vercel (install the Vercel CLI, run `vercel link` inside `site/` once).

### Running it in the cloud every morning

Fork or clone this repo, then add repository secrets (Settings, Secrets and variables, Actions): `APIFY_TOKEN`, `SPOTIFY_CLIENT_ID`, `SPOTIFY_CLIENT_SECRET`. The workflow in `.github/workflows/daily.yml` runs at 8am Pacific, commits the new snapshot, and skips quietly until the secrets exist. To publish the page too, add `VERCEL_TOKEN` (vercel.com, Account, Tokens), `VERCEL_ORG_ID` and `VERCEL_PROJECT_ID` (both in `site/.vercel/project.json` after `vercel link`).

No keys belonging to anyone else are in this repo, and the daily snapshots committed here were collected with the author's own.

To add an artist, add an entry to `releases.json`: Spotify artist ID, the singles already out (track and album IDs), the release date and tracklist, and optionally a checklist and tour dates. The EP or album is detected automatically when it appears on Spotify.

## What switches on over time

| Snapshots | What becomes available |
|---|---|
| 1 | lifetime averages, cities, checklist, short-form pulse |
| 2 | per-day rates on every track and audience metric |
| 3 | trend pills from Spotify popularity movement |
| 15 | week-over-week decay flags from actual play deltas |

## Known limits

- Spotify lists earlier singles as bonus tracks on later single releases, with separate track IDs and the same count. The analyzer keeps one row per song, earliest release, and takes the best popularity score across versions.
- Top cities are Spotify's top five only.
- No Apple Music, YouTube, or radio data yet. YouTube is the obvious next source.
- Short-form reads the artist's own account only. Sounds and UGC on other accounts are not tracked.
- The scrapers depend on Spotify's public page layout. If both fail on a given day the page keeps the last good report and says so.
